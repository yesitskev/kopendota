kopendota

A non-official Kotlin client for the OpenDota API, which serves Dota 2 match, player, hero, team and league data — including the detailed statistics OpenDota extracts from match replays.

The library is a Retrofit service definition plus the models its endpoints return, with a client that assembles the two. Every call is a suspend function, and every response is deserialised with kotlinx.serialization.

Getting started

OpenDotaClient owns the Retrofit, OkHttp, JSON and rate limiting wiring, including the base URL every endpoint path is resolved against:

val client = OpenDotaClient()

val match = client.openDota.getMatch(matchId = 7108753629L)
val wins = client.openDota.getPlayerWinLoss(accountId = 88367253L, heroId = 1L)

Every argument is optional. A subscription carries the API key and the allowances each call is counted against, and the queue bound, serialiser, HTTP logging and timeouts are configured alongside it:

val client =
    OpenDotaClient(
        billingSubscription = BillingSubscription(apiKey = System.getenv("OPEN_DOTA_API_KEY")),
        queueLimit = 500,
        json = Json(from = OpenDotaClient.DEFAULT_JSON) { prettyPrint = true },
        logging = OpenDotaLogging(level = OpenDotaLogLevel.BASIC, logger = { message -> log.debug(message) }),
        timeouts = OpenDotaTimeouts(connect = 5.seconds, read = 60.seconds),
    )

The default serialiser ignores unknown keys, and one of your own should too: OpenDota adds fields over time, and the models here track a single snapshot of the schema.

A client owns an OkHttp connection pool, the threads that serve it and the scope queued calls wait on, so build one and share it rather than creating one per call; close() releases all three. Building the service with Retrofit directly stays an option, and OpenDota carries a worked example — though a service built that way is not rate limited, since nothing holds a call back or counts it.

Things to know

  • Nullability. Every model property is nullable, because OpenDota omits fields it has no data for. A parsed match carries far more detail than an unparsed one, so the replay-derived fields on MatchResponsePlayers are frequently absent.

  • Filters. The player endpoints share a large set of optional query parameters — limit, win, heroId, laneRole and friends. Leaving one at its null default omits it from the request.

  • Rate limits. Every call is held to what a BillingSubscription allows, by a RateLimiter that spends the free allowance — 3,000 requests a day and 60 a minute — before reaching for the subscription, which allows an unlimited day and 3,000 a minute. A call waits where neither allowance has room, and statistics reports what is queued, what is in flight, and what each allowance has spent of its ceiling. submitRequest counts as ten calls against it.

  • IDs. Hero, item, ability, patch, region, game mode and lobby type IDs are resolved through the dotaconstants repository, mirrored by getConstants.

  • Untyped payloads. A few endpoints return shapes that are keyed dynamically or vary by request, so they are exposed as JsonElement rather than a model.
