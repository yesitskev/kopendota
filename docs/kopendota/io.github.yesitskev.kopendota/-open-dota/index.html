OpenDota

interface OpenDota(source)

Retrofit service definition for the OpenDota API.

Each function maps to a single OpenDota endpoint and suspends until the response has been deserialised into the matching model from io.github.yesitskev.kopendota.model. Endpoint paths are relative, so the base URL https://api.opendota.com/api/ is supplied when the service is created — which OpenDotaClient does for you, along with the rate limiting, the API key, the serialiser, HTTP logging and the timeouts. Wiring it up by hand takes:

val json = Json { ignoreUnknownKeys = true }
val openDota: OpenDota =
    Retrofit.Builder()
        .baseUrl("https://api.opendota.com/api/")
        .addConverterFactory(json.asConverterFactory("application/json".toMediaType()))
        .build()
        .create(OpenDota::class.java)

val match = openDota.getMatch(matchId = 7108753629L)
Content copied to clipboard

A service wired up that way carries no rate limiting: nothing holds a call back, counts it or chooses the tier it goes out on, and an API key is only sent if you put one on the request yourself. Build the service through OpenDotaClient for any of that.

Every model property is nullable because the API omits fields it has no data for, and nullable query parameters are left out of the request when they keep their null default.

The API is usable without credentials, at the 3,000 calls a day and 60 a minute that BillingLimits.FREE_TIER describes. Registering an API key raises that: give it to a BillingSubscription and OpenDotaClient spends the free allowance first, then sends the key as the api_key query parameter once the free limits are reached. Hero, item, ability and patch IDs in responses are resolved through the dotaconstants repository, which getConstants mirrors.
