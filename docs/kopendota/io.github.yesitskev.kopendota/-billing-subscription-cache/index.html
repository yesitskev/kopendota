BillingSubscriptionCache

interface BillingSubscriptionCache(source)

Where a BillingSubscription keeps its request counts.

One count is stored per key, and BillingSubscription owns the keys: a count per UTC day, and a count per second that the sliding minute is summed from. Implement this over a shared store — Redis, Memcached, a database table — to hold one allowance across several processes, or leave it at InMemoryBillingSubscriptionCache to count within a single client.

Implementations are called from several coroutines at once and must be safe to share. They may drop a key once its ttl has passed, and a dropped or missing key reads as no requests at all.
